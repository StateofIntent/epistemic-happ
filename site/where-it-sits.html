Where it sits · the Semantic Web

The box nobody ticked

The Semantic Web's original programme had three parts: machine-readable meaning, provenance, and trust. The first two got standards. The third got a name and never got built. This protocol is an attempt at that third box — not the standard for it, which is a different and larger thing, but a working object where there has been an empty slot since 1997.

Figure 1 · the stack as proposed

Eight layers, and the top two never became recommendations

Berners-Lee's layer cake is a dependency stack: each layer uses the capabilities of the ones beneath it. Most of it shipped, and shipped well. The argument on this page is entirely about the top.

Figure 2 · the specification that already existed

The button was designed in 1997, down to what it returns

The trust layer is usually described as vague. It was not. Berners-Lee specified the interaction, the mechanism and the return value in a W3C design note dated 6 February 1997 — a toolbar button marked “Oh, yeah?”, pressed when you lose that feeling of trust, which asks the web so how do I know I can trust this information?

Source. Tim Berners-Lee, Consistent User Interface, W3C Design Issues, 6 February 1997, updated September 1997 — w3.org/DesignIssues/UI.html. The quoted return value is his: the button produces “either a list of assumptions on which the trust is based, or of course an error message indicating either that a signature has failed, or that the system couldn't find a path of trust from you to the page.”

Figure 3 · where the models enter

Language models are not a layer in this stack

The obvious question about the two empty boxes is whether a language model fills them. It is worth answering carefully, because the answer locates the whole problem: models are not a layer at all. The Semantic Web bet that machines could use meaning if the data were made formal. Models got a usable approximation by not doing that — which makes them the stack's competitor rather than one of its components.

Honest limits

Where it is genuinely opposed, stated first

  1. Erasure. Solid exists partly so you can remove your data. This protocol makes erasure structurally impossible — no delete operation is accepted by the network at all, so a right-to-erasure request cannot be complied with by anyone. It is a deliberate trade: a record that can be edited by the party with the most to lose is not a record. A deployment for the general public would have to confront this. The pilot confronts it by being small, consenting and informed.
  2. This is an implementation, not a standard. Filling a slot in the stack with one working system is not the same as specifying the layer, and the difference matters: a standard is something others can implement independently, and this is not that yet.
  3. Proof is not attempted. The layer below Trust is also empty, and nothing here addresses it. A system that stores what was said against a claim is not a system that proves anything.
  4. Two operators is not a network. The trust layer's whole premise is many parties who do not trust each other. The pilot has two, who do.
